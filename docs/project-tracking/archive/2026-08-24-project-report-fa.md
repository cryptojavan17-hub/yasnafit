## ۳. امکانات فعلی (Feature List)

### 🔷 سمت مربی (پنل مدیریت)
1. **داشبورد** — آمار شاگردها، برنامه‌های فعال، نسخه برنامه، آخرین تغییرات
2. **مدیریت شاگردها (CRM)** — جستجو، پرونده با شماره ۶ رقمی، تایم‌لاین، جریان ارزیابی
3. **ارزیابی‌های در انتظار** — بررسی، رد، درخواست تغییر
4. **ساخت برنامه تمرینی (Program Builder)** — ساختار: روز ← سیستم تمرینی ← حرکت ← ست
5. **بانک حرکات ۲,۷۰۷ تایی** — ۵ سیستم تمرینی وب (عادی/سوپرست/تری‌ست/جاینت‌ست/دراپ‌ست)، فیلتر محل ← دسته ← حرکت، جستجو، ست‌ها با وزن/تکرار/استراحت
6. **مرکز اعلان‌ها** — زنگ با شمارنده، پاک‌کردن گروهی، پول ۳۰ ثانیه‌ای
7. **تنظیمات و پشتیبان** — بکاپ SQLite در پوشه `backups`
8. **نسخه و تغییرات** — تاریخچه انتشار ساختاریافته

### 🔷 سمت شاگرد (پورتال جداگانه)
1. ورود با موبایل + رمز (scrypt) و لینک دعوت یک‌بار‌مصرف
2. آنبوردینگ + ویزارد ارزیابی ۱۰ مرحله‌ای (عمومی، اندازه‌گیری‌ها، پزشکی، ورزشی، تغذیه، عادات، بارداری...)
3. داشبورد، مشاهده برنامه، ثبت جلسه تمرین با ست‌های اجراشده
4. پیام‌رسان امن، اعلان‌ها، تاریخچه، پروفایل، تغییر رمز
5. عکس بدن کاملاً اختیاری با راهنمای ژست خنثی + مدارک پزشکی خصوصی

### 🔷 امنیت و زیرساخت
- احراز هویت جداگانه مربی/شاگرد، سشن‌های هش‌شده مستقل
- کوکی‌های HttpOnly + SameSite=Strict
- Rate limiting (لینک دعوت، ورود شاگرد و...)
- CSP، nosniff، بررسی same-origin
- رویدادهای ممیزی ساختاریافته و Redaction
- فایل‌های خصوصی هرگز از `public/` سرو نمی‌شوند

## ۴. روش و مدل برنامه‌نویسی (Architecture)

### الگوی معماری
```
دسکتاپ مربی (BAT ویندوز)
   ↓
SQLite محلی (منبع اصلی حقیقت)
   ↓
سرور (آینده)
   ↓
اپ اندروید شاگرد (آینده)
```

- **Local-First:** همه‌چیز آفلاین روی کامپیوتر مربی؛ لایه‌های آینده: Auth، Sync، Offline، حل تعارض، AI، PDF
- **بدون فریم‌ورک:** سرور HTTP خالص Node.js (بدون Express)، دیتابیس با `node:sqlite` داخلی، فرانت‌اند Vanilla JS + HTML + CSS
- **لایه Sرویس (Service Layer):** منطق در `src/*-service.js` (program، student، assessment، engagement، upload، release و...) جدا از سرور
- **جدول‌های نرمال‌شده = منبع حقیقت:** برنامه‌ها در ۵ جدول نرمال (training_programs → program_days → exercise_systems → program_movements → movement_sets) ذخیره می‌شوند؛ JSON فقط برای انتقال/بکاپ
- **مایگریشن نسخه‌ای و idempotent** با BEGIN/COMMIT/ROLLBACK
- **آماده Sync:** ستون‌های `stable_id` (UUID)، `version`، `created_at/updated_at`، حذف نرم با `deleted_at`
- **مدل ID صریح:** `exercises.id` (PK داخلی) جدا از `original_id` (شناسه دیتاست ۲,۷۰۷ تایی)
- **تست رگرسیون + e2e** — ۹ اسکریپت تست با assert سخت‌گیرانه

| برنامه‌ساز | درایور (Drawer) انتخاب حرکت: محل (باشگاه/منزل) ← دسته + جستجو ← کارت حرکت با تصویر؛ نشان حجم (روز/حرکت/ست) |

## ۶. قوانین پروژه (Rules)

### قوانین Git و همکاری
1. **فقط شاخه‌های تسک Arena** — هرگز مستقیم روی `main` کار نمی‌شود
2. فایل‌های حجیم از Git خارج‌اند: `data/`، `backups/`، `logs/`، عکس‌های ایمپورت‌شده (۱,۸۸۸ عکس/۶۰MB) و `public/assets/videos/`

### قوانین واژگانی (Terminology)
3. **«اصطلاح ممنوع پروژه» هرگز نوشته نمی‌شود** — فقط «شاگرد»؛ تست رگرسیون کل مخزن را اسکن می‌کند و در صورت یافتن، بیلد fail می‌شود

### قوانین داده
4. جدول‌های نرمال‌شده منبع حقیقت‌اند؛ JSON فقط نمای همگام‌شده
5. همه FKها به `exercises.id` داخلی اشاره می‌کنند؛ `original_id` فقط برای سازگاری ایمپورت
6. هش‌ها با فرمت `/^[a-zA-Z0-9_-]{4,64}$/` و بدون تکرار در کل برنامه
7. حذف نرم (`deleted_at`) برای موجودیت‌های sync؛ حذف سخت فقط داخل تراکنش ویرایش برنامه
8. مایگریشن‌ها باید idempotent و تراکنشی باشند

### قوانین امنیت
9. عکس‌های خصوصی/مدارک هرگز از `public/` سرو نشوند؛ مالکیت از سشن استخراج می‌شود
10. بررسی same-origin برای تغییرات شاگرد + Rate limiting روی نقاط حساس
11. **هیچ AI در پروداکشن صدا زده نمی‌شود** (ساختار `assessment_ai_suggestions` خفته است)
12. عکس بدن کاملاً اختیاری، بدون اجبار به انتخاب «امتناع»

### قوانین دامنه (Business)
13. برنامه ماهانه دقیقاً بازه ۳۰ روزه دارد (شروع/پایان)
14. دقیقاً ۳ لینک دعوت با سشن هش‌شده مستقل
15. نسخه‌بندی معنادار (SemVer) + ثبت هر انتشار با مایگریشن

### قوانین فلوی برنامه‌سازی (از سیستم «افزودن نمونه برنامه تمرینی»)
16. ترتیب ثابت: متادیتا ← جلسات ← تمرینات ← سیستم تمرینی ← محل ← دسته ← حرکت ← ست
17. تعداد حرکت هر سیستم: ۱ حرکتی (معمولی/رست پاز/دراپ ست/پس خستگی/FST7/۲۱)، ۲ حرکتی (سوپرست/تکرار نیمه)، ۳ حرکتی (تری ست/۲۰-۱۰-۵)، ۴ حرکتی (جايت ست)، ۵ حرکتی (ماموت ست)
18. **ساخت حرکت غیرواقعی ممنوع** — فقط حرکات موجود در بانک/کتابخانه ویدیو
